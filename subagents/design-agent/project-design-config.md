## Brand & aesthetic
- **Theme:** light **and** dark (theme-aware, WCAG 2.2 AA in both). Status never by colour alone — always icon + text.
- **Primary:** teal `#1AAFBF` (TekHqs app default `--color-primary`). Used for accents, focus, charts, small fills.
  A darker `--color-primary-fill` (`#0E7A88`) carries interactive fills so white text passes AA.
- **Accents:** navy `#061020` (`--color-accent1`), deep teal `#0d4a50` (`--color-accent2`).
- **Neutrals:** slate ramp (`#0f172a` … `#f8fafc`) — calm, professional recruitment-SaaS ground.
- **Type:** system sans stack; small modular scale; tabular numerals in all data/score columns.
- **Feel/positioning:** professional recruitment-SaaS — conventional over gimmicky, legible-not-oversized, calm chrome + a confident teal accent (60-30-10).
- **Locked brand rules:** status never colour-alone; AI-generated content is always disclosed; a human-review/confirm gate precedes any locked decision (criteria, JD); recommendation shows its inputs (auditable, not a black box).

## Tokens
- **Token source (planned):** `src/index.css` (`:root` CSS custom properties) — colours via **inline `style`** in components (Tailwind v4 CSS-var utility classes don't resolve reliably); layout via flex/grid classes. Shared style objects in `src/utils/formStyles.js`.
- **Real token names** (canonical set, see `designs/recruiter-dashboard/tekhqs-ui-kit` in each mockup's `<style>`):
  - Brand: `--color-primary` `--color-primary-fill` `--color-primary-hover` `--color-primary-soft` `--color-primary-soft-text` `--accent-navy` `--accent-teal-deep`
  - Surfaces: `--bg-app` `--surface` `--surface-2` `--surface-3` `--surface-inset`
  - Text: `--text` `--text-secondary` `--text-muted` `--text-on-primary`
  - Borders: `--border` `--border-strong`
  - Inputs: `--input-bg` `--input-border` `--input-border-focus` `--input-placeholder`
  - Status (bg / text / border each): `--success-*` `--warning-*` `--danger-*` `--info-*` `--neutral-*`
  - Focus: `--focus-ring`; Radius: `--radius-sm` `--radius` `--radius-lg` `--radius-pill`
  - Elevation: `--shadow-sm` `--shadow` `--shadow-lg`; Spacing: `--space-1..8` (4/8 scale)
- **AA-fail trap:** `--color-primary` (`#1AAFBF`) FAILS as text on white and as a white-text button fill
  (~2.4:1). Use `--color-primary-fill` (`#0E7A88`) for fills, `--color-primary-soft-text` (`#0B616D`) for text.
- **Status text tokens are the AA-safe darker values** (e.g. `--success-text` `#166534`, not bright green) —
  use them for value text, never the bright semantic hue.

## Locked rules (seed — fills as the user iterates)
- Status pills = icon + text (never colour alone). Recommendation bands map to status tokens (see below).
- Recommendation → token: STRONG_YES→success, YES→brand teal, MAYBE→warning, REVIEW→info (flag icon), NO→neutral/danger.
- Importance chips → token: must_have→danger, very_important→warning, important→info, good_to_have→success.
- Button bindings: primary CTA = `.btn-primary` (fill `--color-primary-fill`); inline/subordinate = `.btn-secondary`/`.btn-ghost`; destructive = `.btn-danger`.
- AI-generated content always shows an "AI" disclosure pill; locked decisions require a human confirm step.

## Stack-mapped pattern playbook
- Progressive disclosure → candidate detail tabs + expandable transcript; criteria editor generate→review→confirm.
- Skeleton loading → `.skel` tiles for tables/KPIs while parsing/scoring.
- Bento dashboard → Overview KPI/funnel/call-stats tiles (Direction C leans fully into this).
- Empty states → icon + next action (e.g. "No criteria yet → Generate with AI").
- Data-table power patterns → sticky header, sort/filter, first-column lock, pagination "X–Y of N", `overflow-x:auto`.
- Wizard → criteria confirm flow (Direction B leans into this as a stepper).
